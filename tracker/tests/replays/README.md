# Replay test bank

Each folder is one case: crops of the loot list and the crafting panel, and what the tracker must count from them.
`KinahLedger.exe replay-bank tracker/tests/replays` runs every case through this version's readers; the release
workflow runs it before publishing, and a case that counts differently stops the release.

- `seed-*`: generated by `replay-bank --seed` from the panel's measured geometry and drawn text, so the bank is never
  empty. They check the plumbing (the panel race on two screen sizes, a loot list row counted without a chat line).
- `report-*`: players' miscount reports, sent with Options › Sharing › "Send report pictures" (loot list and crafting
  panel only, never the chat). `node tools/replays/pull.js` brings new ones here as **pending**: they run and print,
  but never fail a release until someone sets what the right count is.

Turning a pending case into a test: run the bank, look at the pictures and at what it counted. Then either write the
right count into its `expect` by hand and set `"pending": false`, or, when this version's count is the right one,
`KinahLedger.exe replay-bank tracker/tests/replays --record <case folder>`. Look through each report's pictures
before committing it; drop one that shows anything but loot rows or the crafting panel.

`case.json`: `game` (the window size the crops come from), `frames` (`t` time, `k` loot or craft, `f` file, `x`/`y`
the crop's place in the game window), `expect` (`craft_ok`, `craft_fail`, `items` by name, `kinah`; only what is named
is checked), `needs_ocr` (skipped, not failed, on a machine without Windows text recognition), `pending`.

- `text-*`: a trace instead of pictures (`"trace": "trace.jsonl"`), one read per line: `{"t", "k", "l": [...]}` with `k`
  `chat`, `list`, `zone` or `gather` (the gathering bar finishing a race: `ok`, `fail`, `upgrade ok`, `upgrade fail`). A
  `list` read may also carry `y` (each row's top in the window) and `c` (its text's contrast, 0 to 1), as trace.log
  writes them since 2026-10-24; without them rows sit 30 px apart and every read counts, as before. `expect` may name
  `list_unsure`: loot list rows that went before their text settled (logged, never counted).
- `text-2026-10-24-row-*`: the loot list's rows tracked by their slot (brief item 2): a change in place, a row seen once
  while fading in, two identical rows in two slots, a settled row misread as it fades out. Each fails on 0.8.25's
  text-keyed rows and passes with `Session/LootRows.cs`.
- `text-2026-10-24-notrow-*`: lines in the loot list's band that aren't rows (`Session/LootNotRow.cs`): the nameplate
  "Vanguard of Atreia" read as "Vangi" in the top slot beside a fight's rows, and the campsite's name standing in the
  band in Kraka Footpath. Each counts only the real pickup and names `list_notrow` (lines dropped, logged once per text
  per minute); both fail on 0.8.26. A `list` read may also carry `b` (each row's background) and `s` (the spread where
  its icon sits), as trace.log writes them since then; a `plate` read names a nameplate or target name on screen
  (hand-written from reads.log's `fighting:` lines; trace.log doesn't keep them).
- `text-2026-10-24-rows-*`: the list as the 10 fps footage of 2026-10-24 shows it (kinah-bench `timing.md`, `kills.md`,
  `truth-*.csv`), generated by the same simulation: a new row pushing the older ones up, a scrolling Soul row over five
  reads, the player's title in the band for 60 s, two souls with one "Obtained 2" line, a Kina row 0.2 s after its chat
  line, a soul picked 4.5 s after its kill, and a row behind a full-screen window back 6 s later. Each pass reads the list,
  then the chat. A `list` read may carry `h` (each row's icon hash, hex), as trace.log writes it since then; a `cover`
  read is a pass that skips the list (a window over it). `KL_BANK_KEEP=1` keeps each case's reads.log.
- `text-2026-10-24-title-static-band`: Steven's trace.log, 13:10:28 to 13:13:40 local, as recorded (rows with `y`, `c`,
  `b`, `s`, `h`; chat kept only for the game's own lines, players' lines replaced by filler; the four gathering bar
  races from reads.log). The player's title stands in the band the whole time, read about 110 times as "Vangi", "Vangt",
  "Vqng(" and more, while Kina, a soul row, Sapphire Gemstone and Orichalcum gathers come and go below; it is static
  text after three reads over 6 s (one title read goes unsure before that; main had 38). A `list` read may carry `x`
  (each line's left in the window), as trace.log writes it since then (`LootNotRow` rule e).
